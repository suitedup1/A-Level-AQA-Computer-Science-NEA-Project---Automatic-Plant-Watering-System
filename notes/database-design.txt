This is the first draft of something that I might use to store information. However, the aim here is to create a fully normalised table. Currently this would satisfy 1NF if i started putting values into cells, as each timestamp is going ot have only one value per cell in the record.

PollingID is the intended primary key for this data. However if i started inputting values into records, a problem that would arise is that there would be repeated instances of PlantID, PlantAge  and PlantName. A new table would solve that issue, splitting them apart as such:


Now all information about the plant is stored in the Plant table, removing the need to repeat data and preventing update anomalies.  However, not all Action and Alert Types are saved in a table. For example in the Polling table, the entries aren’t guaranteed to include every action and alert types. I will create AlertIDs so that every type is saved. The only action the plant can take is to water so I can create an attribute called IsWatered with Boolean values.
